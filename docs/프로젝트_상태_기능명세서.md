# 프로젝트 상태 및 보관 기능 명세서 v0.1

## 1. 프로젝트 상태

| 저장 코드 | 화면 표시 |
|---|---|
| `in_progress` | 진행중 |
| `maintenance` | 유지보수중 |
| `on_hold` | 보류 |
| `archived` | 보관 |

- 새 프로젝트의 기본 상태는 `in_progress`이다.
- 생성·편집 화면에서는 보관을 제외한 세 가지 활성 상태만 선택할 수 있다.
- 보관 상태는 별도의 프로젝트 보관 기능으로만 설정한다.
- 보관된 프로젝트도 좌측 프로젝트 목록에 상태와 함께 표시한다.
- 보관된 프로젝트의 이름만 편집하면 보관 상태를 유지한다. 활성 상태를 선택해 저장하면 해당 상태로 복구한다.
- 좌측 프로젝트 목록은 진행중, 유지보수중, 보류, 보관 순서로 그룹화한다.
- 각 상태 그룹은 제목을 눌러 프로젝트 목록을 펼치거나 숨길 수 있으며 처음에는 펼쳐져 있다.
- 상태 그룹의 펼침 여부는 브라우저에 저장해 페이지 이동이나 브라우저 재실행 후에도 유지한다.
- 좌측 상단의 프로젝트 총 개수에는 보관 상태의 프로젝트를 포함하지 않는다.

## 2. 프로젝트 보관

- 실제 데이터 삭제는 수행하지 않는다.
- 해당 프로젝트에 `closed`가 아닌 오류가 하나라도 있으면 보관할 수 없다.
- 오류가 없거나 모든 오류가 `closed`이면 프로젝트 상태를 `archived`로 변경한다.
- 보관 조건은 화면과 관계없이 서버의 조건부 UPDATE에서 검사한다.

## 3. 데이터베이스 적용

- 새 데이터베이스는 `ddl/schema.sql`을 사용한다.
- 기존 데이터베이스는 `ddl/migrations/20260914_add_project_status.sql`을 실행한다.
- `working` 상태를 `on_hold`로 변경할 때는 `ddl/migrations/20260914_rename_working_to_on_hold.sql`을 실행한다.
