# 오류 수정 화면 명세서 v0.1

- 대상 화면: 오류 수정 (담당: 본인)
- 참고 문서: `docs/오류상세_화면명세서.md`, `docs/오류등록_화면명세서.md`(필드 구성 동일)

## 1. 진입 경로

오류 상세 화면 메타 정보 바(담당자변경·상태변경·종료·재오픈 버튼이 있는 영역)에 "수정" 버튼을 추가한다.
클릭하면 **별도 페이지**(`/issues/{id}/edit`)로 이동해 현재 값이 채워진 폼을 보여준다.
저장하면 상세 화면(`/issues/{id}`)으로 돌아간다. "취소"를 누르면 저장 없이 상세 화면으로 돌아간다.

오류 등록 화면(`docs/오류등록_화면명세서.md`)과 레이아웃·필드 구성이 동일하다 — 등록 폼의 JSP를
기반으로 만들되, (1) 기존 값이 채워져 있고 (2) 기존 첨부파일이 표시되고 개별 삭제가 가능하다는 점이 다르다.

## 2. 화면 구성

| 순서 | 항목 | 입력 위젯 | 비고 |
|---|---|---|---|
| — | 현재 프로젝트 | 텍스트 표시(수정 불가) | 등록 폼과 동일 |
| 1 | 제목 | text input | 기존 값 채움 |
| 2 | 심각도 | select | 기존 값 선택 |
| 3 | 우선순위 | select | 기존 값 선택 |
| 4 | 발생 위치 | text input | 기존 값 채움 |
| 5 | URL 주소 | text input | 기존 값 채움 |
| 6 | 테스트 버전 | text input | 기존 값 채움 |
| 7 | 테스트 환경 | text input | 기존 값 채움 |
| 8 | 재현 순서 | textarea | 기존 값 채움(줄바꿈 그대로 복원) |
| 9 | 기대 결과 | textarea + 첨부 드롭존 | 기존 값 + 기존 첨부(제거 가능) + 신규 첨부 추가 가능 |
| 10 | 실제 결과 | textarea + 첨부 드롭존 | 위와 동일 |
| 11 | 개선 방향 | textarea | 기존 값 채움 |
| 12 | 첨부파일(일반) | 드래그앤드롭 + 파일 선택 + **기존 첨부 목록(제거 가능)** | 등록 폼과 달리 기존 항목이 미리 표시됨 |

**담당자/상태는 이 화면에서 다루지 않는다** — 이미 상세 화면에서 별도 버튼으로 바로 바꿀 수 있으므로 중복
UI를 만들지 않는다(사용자 확인 완료: 진입 버튼은 메타 정보 바에 두되, 그 버튼들 옆에 "수정"만 추가).

## 3. 기존 첨부파일 표시/삭제 규칙

- 일반/기대결과/실제결과 각 드롭존 위에 해당 컨텍스트의 기존 첨부 썸네일을 먼저 나열한다.
- 각 기존 첨부 썸네일에는 "삭제" 표시(×)가 있어 클릭하면 화면에서 즉시 사라지고, 저장 시 함께 삭제 요청된다.
  실제 삭제는 저장(수정 완료) 버튼을 눌러야 반영된다 — 다른 필드처럼 "취소" 시 원상 복구.
- 새로 추가한 첨부는 등록 폼과 동일하게 드롭존 아래 목록에 나타나고 제출 전 개별 취소 가능.
- 기존 첨부 삭제 표시와 신규 첨부 추가 목록은 별도 UI 영역(서로 섞이지 않음) — 혼동 방지.

## 4. 버튼

| 버튼 | 동작 |
|---|---|
| 수정 완료 | 저장 요청 전송(필드 변경 + 신규 첨부 추가 + 표시된 기존 첨부 삭제), 성공 시 상세 화면으로 이동 |
| 취소 | 확인 없이 즉시 상세 화면으로 복귀, 어떤 변경도 반영되지 않음(삭제 표시했던 것도 취소됨) |

## 5. 동시성 충돌

상세 화면과 동일한 방식 — 폼에 `expectedUpdatedAt`(진입 시점의 `issues.updated_at`, 원본 정밀도 그대로)을
hidden 필드로 들고 있다가 제출 시 같이 보낸다. 저장 시점에 다른 사람이 먼저 수정했다면(충돌) 저장 없이
`/issues/{id}?conflict=true`로 돌아간다(상세 화면의 기존 충돌 배너 재사용).

## 6. 참고

- 색상·타이포·드롭존 스타일은 `docs/오류등록_화면명세서.md`와 동일 기준
- 담당자/상태/종료/재오픈은 상세 화면 자체 버튼으로만 처리(이 화면 범위 아님)
