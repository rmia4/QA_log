QA 관리 웹페이지 — DB 테이블·필드 명세 v0.1

**1. 공통 규칙**

- 테이블명: 복수형 `snake_case`
- 필드명: 단수형 `snake_case`
- 기본키: `id`
- 외래키: `project_id`, `issue_id`, `user_id`처럼 대상명 사용
- 시간: `created_at`, `updated_at` 등 `_at` 접미사 사용
- 시간은 UTC로 저장하고 화면에서는 한국 시간으로 표시
- ID의 실제 자료형과 길이는 기술 구성 단계에서 결정
- 문자열 선택 항목은 미입력 시 `NULL`로 통일
- 아래 ‘필수’는 DB 저장 조건이다. 자동 생성되는 값은 사용자가 입력하지 않는다.
- 오류 등록 화면에는 필수 입력 항목이 없다.

**2. 테이블 목록**

| 테이블명 | 용도 |
|---|---|
| `users` | 사용자 계정 |
| `team_settings` | 팀 공용 가입 코드 설정 |
| `projects` | 프로젝트 |
| `issues` | 오류 |
| `issue_attachments` | 오류 첨부파일 |
| `issue_comments` | 오류 댓글 |
| `issue_histories` | 오류 변경 이력 |

프로젝트별 접근 제한과 고정 QA·개발 역할은 사용하지 않으므로, 프로젝트 참여자·업무 역할 테이블은 두지 않는다.

**3. 사용자 — `users`**

| 필드명 | 논리 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | ID | O | 사용자 고유 ID, 자동 생성 |
| `login_id` | 문자열 | O | 로그인 아이디, 중복 불가 |
| `password_hash` | 문자열 | O | 비밀번호 해시, 원문 저장 금지 |
| `display_name` | 문자열 | O | 화면에 표시할 이름 |
| `created_at` | 일시 | O | 가입 시각, 자동 기록 |
| `updated_at` | 일시 | O | 계정 정보 변경 시각, 자동 기록 |

아이디는 앞뒤 공백을 제거하고 영문 대소문자를 구분하지 않는 기준으로 중복 검사한다. 표시 이름은 중복을 허용한다.

이메일·비밀번호 복구·임시 비밀번호 발급 필드는 두지 않는다.

**4. 팀 설정 — `team_settings`**

현재 서비스는 하나의 팀이 여러 프로젝트를 사용하는 구조이며, 설정 행 하나를 유지한다.

| 필드명 | 논리 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | ID | O | 설정 고유 ID |
| `invite_code_hash` | 문자열 | O | 가입용 팀 공용 코드의 해시 |
| `created_at` | 일시 | O | 설정 생성 시각 |
| `updated_at` | 일시 | O | 설정 변경 시각 |

가입할 때 입력한 코드가 일치하는지 확인한다. 가입에 사용한 코드 원문은 사용자 테이블에 저장하지 않는다.

코드 변경 방법과 관리 화면은 별도 결정 사항이다.

**5. 프로젝트 — `projects`**

| 필드명 | 논리 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | ID | O | 프로젝트 고유 ID, 자동 생성 |
| `name` | 문자열 | O | 프로젝트명 |
| `created_by` | ID | O | 생성자 → `users.id`, 자동 기록 |
| `created_at` | 일시 | O | 생성 시각 |
| `updated_at` | 일시 | O | 변경 시각 |
| `status` | 문자열 | | 프로젝트 상태 |
프로젝트명 필수 조건은 오류 입력 양식과 별개인 제안이다. 모든 참가자가 프로젝트를 생성·조회할 수 있다.

빈 등록 양식도 시스템 자동값만으로 저장할 수 있다.

**7. 첨부파일 — `issue_attachments`**

| 필드명 | 논리 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | ID | O | 첨부 고유 ID |
| `issue_id` | ID | O | 소속 오류 → `issues.id` |
| `original_name` | 문자열 | O | 사용자가 올린 원본 파일명 |
| `storage_key` | 문자열 | O | 서버 저장 위치를 식별하는 고유 키 |
| `mime_type` | 문자열 | O | 서버가 확인한 파일 형식 |
| `size_bytes` | 정수 | O | 파일 크기, 바이트 |
| `uploaded_by` | ID | O | 업로드한 사용자 → `users.id` |
| `created_at` | 일시 | O | 업로드 시각 |

파일 본문은 서버의 첨부파일 저장소에 보관하고, DB에는 메타데이터를 저장한다. 첫 버전의 업로드 허용 형식은 스크린샷용 이미지로 제한하는 안이다.

**8. 댓글 — `issue_comments`**

| 필드명 | 논리 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | ID | O | 댓글 고유 ID |
| `issue_id` | ID | O | 소속 오류 → `issues.id` |
| `content` | 긴 문자열 | O | 댓글 내용 |
| `created_by` | ID | O | 작성자 → `users.id` |
| `created_at` | 일시 | O | 작성 시각 |

오류 등록의 선택 입력 규칙과 별개로, 빈 댓글은 저장하지 않는다. 댓글 수정·삭제는 현재 확정된 범위에 포함하지 않는다.

**9. 변경 이력 — `issue_histories`**

| 필드명 | 논리 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | ID | O | 이력 고유 ID |
| `issue_id` | ID | O | 소속 오류 → `issues.id` |
| `change_group_id` | ID | O | 한 번의 작업으로 발생한 이력을 묶는 ID |
| `event_type` | 코드 | O | 생성·필드 변경·첨부·댓글 이벤트 |
| `field_name` | 문자열 | — | 변경된 필드명, 예: `status`, `title` |
| `old_value` | JSON 값 | — | 변경 전 값 |
| `new_value` | JSON 값 | — | 변경 후 값 |
| `related_record_id` | ID | — | 이벤트에 연결된 첨부 또는 댓글 ID |
| `actor_id` | ID | O | 작업자 → `users.id` |
| `created_at` | 일시 | O | 작업 시각 |

필드 변경은 변경된 필드마다 한 행씩 기록한다. 한 번에 제목과 담당자를 변경하면 동일한 `change_group_id`로 두 행을 남긴다.

`related_record_id`는 첨부·댓글 이벤트에서만 사용하며, 대상 테이블은 `event_type`으로 구분한다. 일반 외래키처럼 두 테이블을 동시에 참조하도록 정의하지 않는다.

이력은 사용자가 직접 수정하지 않는다. 오류 변경과 이력 저장은 하나의 작업으로 성공하거나 실패하도록 처리한다.

**10. 공통 코드값**

| 구분 | 저장값 | 화면 표시 |
|---|---|---|
| 상태 | `new` | 신규 |
| 상태 | `reviewing` | 확인 중 |
| 상태 | `fixing` | 수정 중 |
| 상태 | `closed` | 종료 |
| 심각도 | `unspecified` | 미지정 |
| 심각도 | `low` | 낮음 |
| 심각도 | `medium` | 보통 |
| 심각도 | `high` | 높음 |
| 심각도 | `critical` | 치명적 |
| 우선순위 | `unspecified` | 미지정 |
| 우선순위 | `low` | 낮음 |
| 우선순위 | `normal` | 보통 |
| 우선순위 | `high` | 높음 |
| 우선순위 | `urgent` | 긴급 |
| 이력 종류 | `created` | 오류 등록 |
| 이력 종류 | `field_changed` | 필드 변경 |
| 이력 종류 | `attachment_added` | 첨부 추가 |
| 이력 종류 | `comment_added` | 댓글 작성 |

상태 변경·종료·다시 열기는 모두 `field_changed`와 `field_name = status`로 기록한다.

**11. 목록 조회·상태 변경 규칙**

- 진행 중 오류: 선택한 `project_id`에 속하면서 `status != closed`
- 수정된 오류: 선택한 `project_id`에 속하면서 `status = closed`
- 종료: `status = closed`, `closed_by = 현재 사용자`, `closed_at = 현재 시각`
- 다시 열기: `status = new`, `closed_by = NULL`, `closed_at = NULL`
- 과거 종료 정보는 변경 이력에 보존
- 이미 종료된 오류의 일반 내용을 수정해도 종료 시각은 유지
- 수정된 오류 전용 테이블이나 별도 복사본은 만들지 않음
- 필수 재검증 단계나 재검증자 필드는 두지 않음

**12. 관계·인덱스·데이터 유지**

관계:

- `projects` 1 : N `issues`
- `issues` 1 : N `issue_attachments`
- `issues` 1 : N `issue_comments`
- `issues` 1 : N `issue_histories`
- 사용자 참조 필드는 모두 `users.id`에 연결

권장 인덱스:

- `users.login_id`: 고유
- `issues.issue_number`: 고유
- `issues(project_id, status, updated_at)`: 프로젝트별 오류 목록
- `issues(project_id, assignee_id, status)`: 담당자 필터
- `issue_attachments(issue_id, created_at)`
- `issue_comments(issue_id, created_at)`
- `issue_histories(issue_id, created_at)`

공동 편집 시에는 읽었을 때의 `updated_at`과 현재 값을 비교해, 다른 사용자의 변경을 조용히 덮어쓰지 않도록 한다.

사용자·프로젝트·오류 삭제는 아직 합의된 기능이 아니다. 첫 버전에는 삭제 기능과 연쇄 삭제를 추가하지 않고, 관련 데이터와 이력을 보존한다.
