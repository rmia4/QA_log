# 오류 상세 화면 명세서 v0.1

- 대상 화면: 오류 상세 (담당: 본인)
- 참고 문서: `writing-block.md`(DB 스키마), `QA_log_ERD_v0.1.drawio`(동기 ERD — location_url/suggested_fix 반영 전 버전)
- 참고 목업: 와이어프레임 아티팩트(2026-09-10 제작, 화이트 톤 확정본)

## 1. 화면 진입 경로

좌측 프로젝트 목록(고정, 메인 화면 소관) → 우측 오류 목록에서 항목 클릭 → 우측 영역만 상세 화면으로 전환.
좌측 프로젝트 목록은 그대로 유지되고, 상세에서 목록으로 돌아가면 검색·필터 상태가 保존된다(메인 화면 소관 영역과의 계약).

오류 등록·수정도 같은 우측 영역에서 진행하며, 저장 후에는 상세 화면으로 이동한다.

## 2. 레이아웃 — 4개 영역

### 2.1 헤더

| 요소 | 내용 |
|---|---|
| 브레드크럼 | `{프로젝트명} / #{issue_number}` |
| 중요도 배지 | 심각도(`severity`)·우선순위(`priority`)를 나란히, 제목보다 먼저 배치. 서로 다른 색 계열(심각도=적색 계열, 우선순위=주황/호박색 계열)로 혼동 방지 |
| 상태 배지 | `status`를 점(dot) + 텍스트 pill로 표시 |
| 제목 | `title`, 비어 있으면 "제목 없음" 표시(저장값 아님) |

**배지 색상 매핑**

| 구분 | 코드값 | 화면 표시 | 비고 |
|---|---|---|---|
| 심각도 | unspecified/low/medium/high/critical | 미지정/낮음/보통/높음/치명적 | 톤이 진해질수록 심각 |
| 우선순위 | unspecified/low/normal/high/urgent | 미지정/낮음/보통/높음/긴급 | 톤이 진해질수록 긴급 |
| 상태 | new/reviewing/fixing/closed | 신규/확인 중/수정 중/종료 | dot 컬러만 구분, 배지 자체는 중립톤 |

### 2.2 메타 정보 바

| 요소 | 내용 |
|---|---|
| 등록자 | `created_by` 표시명 + `created_at` |
| 현재 처리 담당자 | `assignee_id` 표시명 — 강조 스타일(배경 tint + 굵게), 미지정이면 "미지정" |
| 최근 변경 | `updated_by` 표시명 + `updated_at` |
| 액션 버튼 | 담당자 변경 / 상태 변경 / 종료(또는 다시 열기 — 3.3 참고) |

### 2.3 본문 — 오류 내용

아래 순서·라벨로 고정 표시(모두 선택 입력이라 빈 값이면 "—" 등으로 표시):

1. 발생 위치 (`location`)
2. URL 주소 (`location_url`) — 값이 있으면 클릭 가능한 링크로 렌더링
3. 재현 순서 (`steps_to_reproduce`) — 줄 단위 번호 목록
4. 기대 결과 (`expected_result`)
5. 실제 결과 (`actual_result`)
6. 테스트 버전 (`test_version`)
7. 테스트 환경 (`test_environment`)
8. 개선 방향 (`suggested_fix`) — 강조 배경 박스로 구분
9. 첨부파일 (`issue_attachments`) — 썸네일 그리드, 클릭 시 원본 확인/다운로드

### 2.4 하단 — 탭 (변경 이력 / 댓글, 분리형)

레딧 스타일 커뮤니티 UI는 **댓글 탭에만** 적용하고, 변경 이력은 별도 시스템 로그 스타일로 둔다(2026-09-10 확정 — 통합 타임라인 아님).

**탭 A. 변경 이력**
- `issue_histories`를 시간순(오래된 것부터) 나열, 시스템 로그 한 줄 스타일
- `event_type`별 표시 규칙은 기능 명세서 3.4 참고
- `comment_added` 이벤트는 감사 목적으로만 저장되고 이 탭에는 노출하지 않음(댓글 탭과 중복 방지)

**탭 B. 댓글**
- `issue_comments`를 시간순으로 카드형 렌더링(작성자 아바타/이름/시간 + 본문)
- 입력창은 탭 하단 고정
- 대댓글(답글)은 현재 범위에 없음(단일 계층) — 추후 필요 시 `parent_id` 추가로 확장 가능하도록 설계만 열어둠

기본 열림 탭: 댓글(요구사항의 핵심 기능이라 우선 노출).

## 3. 상태 전이와 화면 반응

- 등록 → (상태 변경) → 종료 → 오류 목록의 "수정된 오류" 탭으로 자동 이동
- 종료된 오류도 상세 화면 구조·이력·댓글은 동일하게 유지
- "다시 열기" 클릭 시 상태를 `new`로 되돌리고, 목록에서는 다시 "진행 중 오류" 탭에 노출
- 재검증 전용 필수 단계나 별도 검증자 필드는 없음(누구나 상태 변경·종료·재오픈 가능)

## 4. 참고

- 색상·타이포 등 상세 톤은 와이어프레임 아티팩트 기준(화이트/라이트그레이 배경, 파란 액센트, 흑백 톤 단계로 라벨/값 구분)
- 동기 화면(메인)과의 접점: 오류 목록에서 이 상세로 넘어올 때 `issue_id` 하나만 전달받으면 되고, 이 화면 자체는 프로젝트/오류 목록 상태를 직접 알 필요 없음
